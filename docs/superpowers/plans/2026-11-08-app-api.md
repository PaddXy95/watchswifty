# App-API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A documented JSON API under `/api/v1` with device-token login, giving an app every function of the web UI.

**Architecture:** `Sources/WatchSwiftyAPI/openapi.yaml` is the single source; Apple's `swift-openapi-generator` build plugin generates types and an `APIProtocol` server; `OpenAPIVapor` mounts it under `/api`. `APIHandler: APIProtocol` (in `Sources/App/API/`) only calls services shared with the web UI; controller logic that is still in controllers moves into services first. Devices log in through the browser (authorization code + PKCE) and get 90-day bearer tokens.

**Tech Stack:** Swift 6.3+, Vapor 4, Fluent/SQLite, swift-openapi-generator 1.14.4, swift-openapi-runtime 1.13.4, swift-openapi-vapor 1.2.0, Swagger UI 5.34.1 (vendored).

**Spec:** `docs/superpowers/specs/2026-11-08-app-api-design.md`

## Global Constraints

- Dependencies: `.package(url: "https://github.com/apple/swift-openapi-generator", from: "1.14.4")`, `.package(url: "https://github.com/apple/swift-openapi-runtime", from: "1.13.4")`, `.package(url: "https://github.com/vapor/swift-openapi-vapor", from: "1.2.0")` (not 2.0 beta).
- Spec: OpenAPI 3.1.0, `servers: [{url: /api}]`, all paths start with `/v1/`, `info.version: 1.0.0`, security scheme `bearerAuth` (HTTP bearer); every operation except `getVersion` and `createToken` declares `security: [{bearerAuth: []}]`.
- Generator config `Sources/WatchSwiftyAPI/openapi-generator-config.yaml`: `generate: [types, server]`, `accessModifier: package`. Generated code is never committed. The project `swiftSettings` are not applied to the `WatchSwiftyAPI` target.
- Errors: body `{"code": String, "message": String}` (schema `Error`), German `message` identical to the web UI texts. Codes and statuses: `unauthorized` 401 (+ `WWW-Authenticate: Bearer`), `tokenExpired` 401, `forbidden` 403, `notFound` 404, `validation` 422, `missingTMDBToken` 422, `selfAction` 422, `noPassword` 409, `invalidGrant` 400, `payloadTooLarge` 413, `tmdbUnavailable` 503.
- JSON field names camelCase English; days `yyyy-MM-dd` strings; timestamps RFC 3339 (`date-time`); services as existing raw values (`netflix`, `prime_video`, `disney_plus`, `apple_tv`, `hbo_max`, `paramount_plus`, `wow`, `cinema`, `purchased`, `other`).
- `/api/v1` ignores session cookies and is exempt from `OriginCheckMiddleware`; `/api/auth/authorize` is not exempt.
- Tokens: `ws_` + 32 random bytes Base64URL (no padding); only SHA-256 hex stored; lifetime 90 days from issue; never logged, shown once.
- Redirect URI allow-list: exactly `watchswifty://auth`.
- Paging: `page` default 1, `perPage` default 50, clamped to 1…200.
- Uploads (multipart field `file`): at most 10 MB for Netflix, 2 MB for film lists → `413 payloadTooLarge`.
- Each phase ends with VERSION bump + CHANGELOG section: phase 1 → `0.2.0`, phases 2–5 → `0.2.1` … `0.2.4`.
- Tests: Swift Testing + VaporTesting via `withTestApp`; full suite `swift test` must pass at every commit.

## Review Focus

1. A multi-megabyte Netflix CSV uploaded through the API (bodies are streamed by OpenAPIVapor, no Vapor limit) → accepted up to 10 MB, `413 payloadTooLarge` above, never unbounded memory. Test: `netflixUploadLimit` (Task 11).
2. A device name with HTML (`<script>`) or umlauts on the consent page → shown escaped and intact. Test: `consentPageEscapesDeviceName` (Task 3).
3. `perPage=100000` or `page=0` on history → clamped, no crash or huge response. Test: `historyPagingIsClamped` (Task 8).
4. Tokens and auth codes must not reach logs or any response except their single creation. Test: `tokenAppearsOnlyOnce` (Task 4) asserts `GET me/devices` and the Konto page never contain the token or its hash.
5. A title never cached before, requested by a user without TMDB token → `422 missingTMDBToken`, not 500; cached titles still answer. Test: `seriesWithoutTMDBToken` (Task 6).

## Shared types (defined in Task 1–2, used by all later tasks)

- `Sources/App/API/APIError.swift`: `struct APIError: Error { let status: HTTPStatus; let code: String; let message: String }` with static members `unauthorized`, `tokenExpired`, `forbidden`, `notFound`, `invalidGrant`, `selfAction`, `noPassword`, `payloadTooLarge`, `validation(_ message: String)`; `static func from(_ error: any Error) -> APIError` maps `TrackingError`, `TMDBError` (`missingToken` → `missingTMDBToken`, `unauthorized`/network → `tmdbUnavailable`), `AbortError`, `OpenAPIRuntime.ServerError` (uses `underlyingError`), else 500 `internal`.
- `Sources/App/API/APIErrorMiddleware.swift`: `struct APIErrorMiddleware: AsyncMiddleware` → JSON error response from `APIError.from`.
- `Sources/App/API/APIContext.swift`: `struct APIRequestState: Sendable { let request: Request; let user: User?; let tokenProblem: APIError? }`; `enum APIContext { @TaskLocal static var current: APIRequestState?; static func request() throws -> Request; static func requireUser() throws -> User; static func requireAdmin() throws -> User }` (`requireUser` throws `tokenProblem ?? .unauthorized`; `requireAdmin` throws `.forbidden` for non-admins).
- `Sources/App/API/APIContextMiddleware.swift`: reads `Authorization: Bearer …`, calls `APITokenService.authenticate`, runs `next` inside `APIContext.$current.withValue(...)`.
- `Sources/App/API/APIHandler.swift`: `struct APIHandler: APIProtocol {}`; one extension file per group: `APIHandler+Meta.swift`, `+Auth.swift`, `+Home.swift`, `+Search.swift`, `+Series.swift`, `+Movies.swift`, `+History.swift`, `+Library.swift`, `+Stats.swift`, `+Account.swift`, `+NetflixImport.swift`, `+FilmList.swift`, `+Admin.swift`.
- Test support `Tests/AppTests/Support/APITest.swift`: `func apiToken(_ app: Application, _ user: User, now: Date = .now) async throws -> String`; `extension HTTPHeaders { static func bearer(_ token: String) -> HTTPHeaders }`.
