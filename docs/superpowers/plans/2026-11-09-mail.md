# E-Mail (Passwort vergessen, Einladungen) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optional SMTP mail, configured by the admin in the UI, for "Passwort vergessen" and for inviting new users.

**Architecture:** SMTP settings live as one `TokenCipher`-sealed JSON block in `app_settings`; users get an optional sealed `email`. `MailService` builds RFC 5322 text mails (`MailMessage`) and hands them to a `MailSender` (live: SwiftySMTPClient; tests: fake) with a 30 s deadline. One-time links (`password_tokens`, SHA-256 hashed) serve both reset (1 h) and invitation (7 d) through one `/reset-password` page. Web and App API call the same services.

**Tech Stack:** Swift 6.3+, Vapor 4, Fluent/SQLite, Elementary/htmx, swift-openapi-generator, SwiftySMTPClient 0.1.x, swift-nio-ssl.

**Spec:** `docs/superpowers/specs/2026-11-09-mail-design.md`

## Global Constraints

- Dependencies: `.package(url: "https://github.com/PaddXy95/SwiftySMTPClient.git", .upToNextMinor(from: "0.1.0"))`, `.package(url: "https://github.com/apple/swift-nio-ssl.git", from: "2.37.5")`; products `SwiftySMTPClient`, `NIOSSL` in target `App`.
- No new environment variables; the `.env`/README config table stays unchanged.
- Secrets at rest: mail settings block and `users.email` sealed with `TokenCipher` (`enc:v1:` prefix, key `TOKEN_KEY`). The SMTP password never appears in any page, API response or log.
- Mask of an address: first character of the local part + `•••@` + domain, e.g. `p•••@idesia.de`. Full addresses of other users never reach admin pages or admin API responses; addresses in logs and SMTP error texts are masked.
- Lifetimes: reset token 3600 s, invite token 7 × 86400 s; forgot-password throttle 300 s per user; send deadline 30 s; SMTP `connectTimeout` 10 s, `replyTimeout` 30 s.
- Links are built only from the stored "Adresse von WatchSwifty": `<baseURL>/reset-password?token=<token>`; never from request headers.
- Tokens: 32 random bytes, Base64URL without padding; only the SHA-256 hex hash is stored.
- API errors: `mailNotConfigured` 422, `mailFailed` 502 (German message), others as before.
- Texts German, tone as the existing pages. Mail subjects exactly: `WatchSwifty: Testmail`, `WatchSwifty: Passwort zurücksetzen`, `Einladung zu WatchSwifty`.
- Tests: Swift Testing + VaporTesting via `withTestApp`; `swift test` passes at every commit.
- Release: `VERSION` → `0.3.0`, CHANGELOG section `## [0.3.0]` (Task 10).

## Review Focus

1. "Adresse von WatchSwifty" entered with a trailing slash or a path (`https://watch.example.lan/`, `https://x/app`) → stored as `https://watch.example.lan`, path rejected; never a link with `//reset-password`. Test: `baseURLNormalized` (Task 2).
2. A mail server that accepts the TCP connection but never replies → the admin's "Testmail senden" answers within the deadline with a timeout message, the page never hangs. Test: `sendHonorsDeadline` (Task 3).
3. Addresses as people paste them (`Pat <p@x.de>`, trailing spaces, `P@IDESIA.DE`, umlauts, `a b@x.de`) → display-name/non-ASCII/space forms rejected with the German message, whitespace trimmed and domain lowercased. Tests: `emailNormalization` (Task 1), `invalidEmailRejected` (Task 7).
4. A server rejection whose text contains the recipient (`550 5.1.1 <alice@example.org> unknown`) → admin sees and log contains only `a•••@example.org`. Test: `describesSMTPErrorsMasked` (Task 3).
5. Deleting a user with a pending invitation or reset link → token rows are gone and the link shows "ungültig", no 500. Test: `tokensGoWithUser` (Task 6).
